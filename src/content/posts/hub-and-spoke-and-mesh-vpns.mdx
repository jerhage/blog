A VPN makes devices on different networks behave as if they shared one private network. Each device gets a private address on that network, and traffic between those addresses travels through encrypted tunnels across the internet. Hub-and-spoke and mesh VPNs build the same kind of tunnel. They differ in where the tunnels go, and that decides which path every packet takes.

## What a tunnel does

When an application sends data to a private address, it builds an ordinary packet: from my private address, to your private address. The internet cannot deliver that packet, because private addresses only mean something inside the VPN. So the VPN software encrypts the whole packet and puts it inside a new one, addressed from this device's public internet address to the other end of the tunnel. The internet delivers the outer packet. The other end removes the wrapping, decrypts the original packet, and handles it as if it had arrived on a local network.

Each end keeps a table that pairs private addresses with tunnels: which private addresses live behind which tunnel, and which public address that tunnel currently leads to. Every routing decision in a VPN comes from that table.

## Hub and spoke

In a hub-and-spoke VPN, every device opens one tunnel, to a central server: the hub. A device's table is one line long. Everything for the private network goes into the tunnel to the hub.

The hub holds the full table. When a packet arrives, the hub decrypts it and reads where it is going. It then looks up which tunnel leads to that private address, encrypts the packet again for that device, and sends it on. A reply takes the same route in reverse. The hub sees the reply's private destination, finds the tunnel that belongs to it, and sends the reply down that tunnel to the device's last known public address.

So every exchange between two devices crosses the hub twice, once in each direction, even when both devices sit in the same room. The hub also does all of the encryption work for everyone. The upside of this shape is that all traffic meets in one place. There is one machine to configure, one place to watch or filter traffic, and one exit to the internet.

## Mesh

In a mesh VPN, every device keeps a tunnel to each peer it talks to. Tailscale works this way. The work splits into two parts. The control plane decides who may talk to whom and how to reach them. The data plane carries the packets.

A coordination server runs the control plane. Each device sends it a public key and the public addresses where it can be reached. The server gives every device a table of the peers it may talk to, with their keys and addresses. It carries none of the traffic itself. With that table, each device does for its own peers what the hub did for everyone: it looks up the peer for a private address and sends the packet straight there.

The hard part is reaching a device that sits behind a home router or an office firewall. These devices answer only traffic that looks like a reply to something they sent. A mesh gets around this by having both devices send to each other at about the same moment. Each router sees its own device send first, so it lets the other side's packets in. When that still fails, the two devices fall back to a relay, a server that passes their encrypted packets along without being able to read them.

## Side by side

| | Hub and spoke | Mesh |
| --- | --- | --- |
| Path between two devices | Through the hub, both ways | Direct, or through a relay when blocked |
| Who knows the full table | The hub | Every device, for its own peers |
| What the central server carries | Every packet | No packets, only keys, addresses and policy |
| If the central server stops | Nothing connects | Existing connections continue; changes wait |
| Where traffic can be watched or filtered | At the hub | On each device |

Both models use the same building block: an encrypted tunnel between two ends and a table that maps private addresses to tunnels. A hub-and-spoke VPN keeps one table in the middle, so the network is a star and every path crosses the center. A mesh gives each device its own table, so the network is a web and each pair of devices has its own path.
